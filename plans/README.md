## How to use

- Every plan is self-contained: it inlines the code excerpts, commands, and conventions you need.
  You do **not** need another plan's context except where "Depends on" names one.
- Run every verification command and confirm the expected result before moving on. If a STOP
  condition triggers, stop and report. Do not improvise.
- Repo verification gates (used by nearly every plan):
  - Build: `go build ./...` → exit 0
  - Vet: `go vet ./...` → exit 0
  - Tests: `go test ./...` and `go test -race ./...` → all pass
  - Lint: `mise exec -- golangci-lint run ./...` → `0 issues.` (golangci-lint 2.15.0 pinned in
    `mise.toml`; run `mise install` once). **Always go through `mise exec --`**: a stale global
    golangci-lint 2.11.4 earlier on PATH fails under Go 1.27 with false
    "export data version 5 is greater than maximum supported version" typecheck errors.
  - Format: `gofmt -l .` → no output
- Toolchain: Go 1.27.3 via mise; `go.mod` directive is deliberately `go 1.26.0`, so don't use
  APIs newer than Go 1.26.
- Many plans touch the same hot files (`internal/m4a/chapters.go`, `internal/mp3/id3v2.go`,
  `internal/flac/parser.go`). Run plans that share a file **one after another, not in
  parallel**. Each plan's drift check (`git diff --stat aca9750..HEAD -- <paths>`) will then fire
  as expected; compare excerpts against the live code as the plan instructs.

## Dependency notes

- **Write support wave (038–042).** The maintainer decided GO in
  `docs/design/020-write-support-decision.md`. The order is MP3 → FLAC → M4A/M4B; Ogg/Opus is
  deferred and has no plan. Chapters are preserved and not editable. Two maintainer rules bind
  every plan in the wave:
  - the API is **stable from day one**;
  - there is **no cross-field inference**: readers and writers never derive one field from
    another.
- **038 → 039 is a hard gate.** 038 ends with a STOP: the executor presents the `go doc` output
  of the new exported surface and an apidiff report. 039 must not start until the maintainer
  signs off and moves 038 to DONE.

  plan is DONE and the gate is green for it.

## Findings considered and rejected / not selected

- **Swap errgroup for sync.WaitGroup**: rejected (July). `golang.org/x/sync` is one
  well-maintained, correctly used dependency; removing it is churn.
- **Opus pre-skip omitted from duration**: cosmetic (tens of ms); can ride along with 019.
- **`Atom.IsContainer` per-call map**: dead code, folded into 017.
- **`OpenReader`/`OpenFS` public reader entry points** (Oct direction): offered, not selected.
  `openReader(ctx, io.ReaderAt, size, path, opts)` already exists unexported (`file.go:~129`) if
  revisited.
- **Multi-file audiobook aggregation (`audiometa/book`)** (Oct direction): offered, not selected.
  It is L effort, and the policy (ordering, tag conflicts) arguably belongs in the consumer.
- **`OpenMany` holding one FD per result / streaming `ScanMany`**: real (`file.go` OpenMany
  returns all open Files) but an API-design decision; noted as deferred in 032.
- **OpenMany concurrency = NumCPU on I/O-bound work**: LOW confidence; revisit only with 035's
  latency-injecting benchmarks.
- **Ogg 64 KB tail read**: marginal allocation; not worth a plan.
- **32-bit `int(uint32)` slice-bound panics in `internal/ogg`**: real only on 386/armv7. Not
  planned; add `GOARCH=386 go test ./...` to CI (018) if 32-bit targets matter.
- **Test coverage for `examples/`, `cmd/atom-dump-tool`, stringer output**: not worth it; CI
  already compiles them. atom-dump-tool's own bugs are handled by 021.
- **ApplyReplayGain formula bug**: recorded in 017's decision table (delete vs fix); no
  standalone plan.
