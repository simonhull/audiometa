## Why this matters

This library parses untrusted binary audio files, yet total statement coverage is
47.4%, there are **zero** fuzz targets, and there is **no `testdata/` directory** —
every fixture is synthetic bytes hand-built to match the parser's own assumptions.
The product's core feature (audiobook chapters) is ~0% covered for every format
except Nero `chpl`; MP3/FLAC artwork extraction is 0%; the public `Open()` →
`Tags`/`Chapters`/`ExtractArtwork()` round-trip is never tested end-to-end. Many of
the other plans in this set change parser behavior on real and malformed input; they
have no regression net until this baseline exists. This plan builds three things: a
small **real-file corpus** generated by ffmpeg/flac, **public-API integration tests**
that open those files, and **fuzz targets** for every parser entrypoint. It changes no
production code — it only makes the codebase's behavior observable and lockable.

## Steps

### Step 1: Write the corpus generator

Create `internal/testcorpus/generate.sh` (make it `chmod +x`). It generates a tiny
(a few seconds of silence) tagged file per format into `testdata/`, using tools that
are present. Target shape:

```sh
#!/usr/bin/env sh
# Regenerates testdata/ fixtures. Requires ffmpeg and flac on PATH.
# Run from repo root: sh internal/testcorpus/generate.sh
set -eu
OUT=testdata
mkdir -p "$OUT"
# 2 seconds of silence as the audio bed
SILENCE="-f lavfi -i anullsrc=r=44100:cl=stereo -t 2"

# MP3 with ID3v2.3 tags (LAME via ffmpeg)
ffmpeg -y $SILENCE -id3v2_version 3 \
  -metadata title="Test Title" -metadata artist="Test Artist" \
  -metadata album="Test Album" -metadata date="2021" \
  -metadata TXXX="series=Test Series" \
  "$OUT/sample.mp3"

# FLAC with Vorbis comments + a cover picture
ffmpeg -y $SILENCE \
  -metadata title="Test Title" -metadata artist="Test Artist" \
  -metadata album="Test Album" "$OUT/sample.flac"

# M4A (AAC) with iTunes-style tags
ffmpeg -y $SILENCE -c:a aac \
  -metadata title="Test Title" -metadata artist="Test Artist" \
  -metadata album="Test Album" "$OUT/sample.m4a"

# Ogg Vorbis
ffmpeg -y $SILENCE -c:a libvorbis \
  -metadata title="Test Title" -metadata artist="Test Artist" \
  "$OUT/sample.ogg"

# Opus
ffmpeg -y $SILENCE -c:a libopus \
  -metadata title="Test Title" -metadata artist="Test Artist" \
  "$OUT/sample.opus"

echo "Generated:"; ls -l "$OUT"
```

Then run it from the repo root: `sh internal/testcorpus/generate.sh`.

**Verify**: `ls testdata/` → shows `sample.mp3 sample.flac sample.m4a sample.ogg sample.opus`,
each non-empty. If `ffmpeg` lacks libvorbis or libopus (the `.ogg`/`.opus` steps error),
that is a STOP condition — report which encoders are missing so the operator can install them.

### Step 2: Write public-API round-trip integration tests

Create `audiometa_corpus_test.go` (package `audiometa_test`). For each fixture in
`testdata/`, call the **public** `audiometa.Open` and assert the metadata that the
generator wrote. This is the first test that exercises `file.go`'s option handling and
`ExtractArtwork`. Target shape:

```go
package audiometa_test

import (
	"testing"

	"github.com/simonhull/audiometa"
)

func TestOpen_Corpus(t *testing.T) {
	cases := []struct {
		path         string
		wantFormat   audiometa.Format
		wantTitle    string
		wantArtist   string
	}{
		{"testdata/sample.mp3", audiometa.FormatMP3, "Test Title", "Test Artist"},
		{"testdata/sample.flac", audiometa.FormatFLAC, "Test Title", "Test Artist"},
		{"testdata/sample.m4a", audiometa.FormatM4A, "Test Title", "Test Artist"},
		{"testdata/sample.ogg", audiometa.FormatOgg, "Test Title", "Test Artist"},
		{"testdata/sample.opus", audiometa.FormatOpus, "Test Title", "Test Artist"},
	}
	for _, tc := range cases {
		t.Run(tc.path, func(t *testing.T) {
			f, err := audiometa.Open(tc.path)
			if err != nil {
				t.Fatalf("Open(%s): %v", tc.path, err)
			}
			defer f.Close()
			if f.Format != tc.wantFormat {
				t.Errorf("Format = %v, want %v", f.Format, tc.wantFormat)
			}
			if f.Tags.Title != tc.wantTitle {
				t.Errorf("Title = %q, want %q", f.Tags.Title, tc.wantTitle)
			}
			if f.Tags.Artist != tc.wantArtist {
				t.Errorf("Artist = %q, want %q", f.Tags.Artist, tc.wantArtist)
			}
		})
	}
}
```

Add a second test `TestExtractArtwork_Caching` that opens `testdata/sample.mp3` (or
whichever fixture the generator embedded art into — if none, use FLAC after adding
`-attach`/cover via a follow-up; if no fixture has art, assert `ExtractArtwork` returns
`(nil-or-empty, nil)` and document that in a comment). Call `ExtractArtwork()` twice and
assert the second call returns the same slice header (cache hit) with no error.

> **Note on encoder variance**: ffmpeg may not write every field identically across
> versions (e.g. the MP3 `TXXX=series` may or may not map to `Tags.Series`). Assert only
> the robust fields (Title, Artist, Format) in the table above. If Title/Artist do **not**
> come back for a given format, that is a real parser finding — record it in your report
> and mark that subtest `t.Skip` with a comment, do not weaken it to always-pass.

**Verify**: `go test -run TestOpen_Corpus ./...` → PASS (or documented skips with recorded findings).

### Step 3: Add fuzz targets for every parser

Create one `fuzz_test.go` per parser package. Each seeds from the corpus and feeds raw
bytes to the parser, asserting only "does not panic" (a parser is allowed to return an
error on garbage; it must never panic). MP3 example — mirror for flac/m4a/ogg:

```go
package mp3

import (
	"bytes"
	"context"
	"os"
	"path/filepath"
	"testing"
)

func FuzzParseMP3(f *testing.F) {
	// Seed from the real corpus if present.
	if data, err := os.ReadFile(filepath.Join("..", "..", "testdata", "sample.mp3")); err == nil {
		f.Add(data)
	}
	f.Add([]byte("ID3\x03\x00\x00\x00\x00\x00\x00")) // minimal header
	f.Add([]byte{})                                    // empty

	p := &parser{}
	f.Fuzz(func(t *testing.T, data []byte) {
		// Must not panic on any input. Errors are fine.
		_, _ = p.Parse(context.Background(), bytes.NewReader(data), int64(len(data)), "fuzz.mp3")
	})
}
```

For the m4a target, also add a seed with an `ftyp`+`moov` skeleton (copy the bytes from
`file_cancel_test.go:22-35` `createTestM4BFile`). For ogg, seed with `testdata/sample.ogg`
and `testdata/sample.opus`.

**Verify**: run each target briefly:
`go test -run '^$' -fuzz FuzzParseMP3 -fuzztime 20s ./internal/mp3/` → exits 0, prints
`elapsed: ..., ... execs`. Repeat for `FuzzParseFLAC ./internal/flac/`,
`FuzzParseM4A ./internal/m4a/`, `FuzzParseOgg ./internal/ogg/`.

> If any fuzz target finds a crasher, Go writes it to `testdata/fuzz/`. **Commit the
> crasher corpus and record the panic in your report** — do not fix the parser here.
> The crasher becomes a regression seed for plans 002/003/004/019. A found crash is a
> successful outcome for this plan, not a failure.
